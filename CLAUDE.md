# Project Rules

Purchase-intent scoring + next-best-action demo on public e-commerce clickstream.
Built to run locally in one command, then port cleanly to Cloudera AI. The guiding
principle is **shared core, swappable edges**: all platform-specific concerns live
behind a thin edge (data connection, serving wrapper, frontend config). Porting swaps
edges; it never rewrites logic.

## Attribution rule (non-negotiable)

- No references to AI assistants, code-generation tools, or their vendors anywhere in
  the repo. This covers code, comments, docstrings, commit messages, READMEs, and any
  generated or committed file.
- No co-authorship trailers, "generated by" notes, or tool attribution of any kind.
- Write everything as first-party, human-authored project work.
- This file is the sole exception: it is tooling config, so its name and contents may
  reference the assistant tooling. The rule applies to every other file in the repo.

## Discipline rules (prevent local leakage)

- No hardcoded file paths or `localhost` in committed code. Read everything from
  `config/` or environment variables (e.g. `API_BASE_URL`).
- `src/core/features.py` is the single feature-prep module, shared by both training and
  serving. Identical preparation on both sides, so there is no train/serve skew.
- `predict(payload: dict) -> dict` in `src/core/predict.py` is a pure, shared function.
  Both the local FastAPI app and the Cloudera model deployment call it unchanged.
  Next-best-action lives *inside* predict so score + action return together and the
  frontend stays dumb.
- Pin every dependency version in `requirements.txt`.
- Persist models in portable formats: XGBoost native (`save_model`) + joblib for the
  sklearn pipeline. Never raw pickle.
- Save the ordered feature schema (`models/feature_schema.json`) alongside the model and
  validate serve-time inputs against it.
- One database access module: swapping DuckDB for Impala changes the connection only,
  not the calling code.
- Document every local -> Cloudera swap in `PORTING.md`.

## Stack constraints

- **Data store:** Plain Parquet on disk locally -> Iceberg table on Cloudera. Same
  schema. The local layer is plain Parquet only; no local Iceberg or PyIceberg catalog.
- **Query engine:** DuckDB locally -> Impala on Cloudera. `sql/features.sql` must be
  ANSI-plain and run on both. No DuckDB-only syntax: no `SELECT * EXCLUDE`, no `QUALIFY`,
  no list types.
- **Model:** `XGBClassifier` inside an sklearn `Pipeline`. Same artifacts local and
  ported. Pin runtime library versions to match training when loading in CML.
- **Serving:** FastAPI wrapping `core.predict` locally -> CML model endpoint (wrap the
  same `predict` function) or CAI Inference Service. Keep the request/response JSON
  envelope thin and documented; confirm the current CML/CAI envelope before porting.
- **Frontend:** React, `API_BASE_URL` from env (never hardcoded) -> built static bundle
  deployed as a CML Application.

## Modeling notes

- Dataset is generic public e-commerce sessions (UCI Online Shoppers), not home goods.
  Frame it as "public e-commerce clickstream, same shape as your Flume data." Verify the
  dataset license before use.
- ~12,330 rows, ~18 features, boolean target `Revenue` (verify exact counts).
- Class imbalance ~15% positive. Handle with `scale_pos_weight`. Evaluate with AUC-ROC
  and PR-AUC, never accuracy.
- `PageValues` is likely the dominant, near-leakage feature. Be ready to report metrics
  with and without it and to explain it.
- Fix one random seed (e.g. `RANDOM_STATE = 42`) and use it for both the train/test
  split and the model so every run is reproducible.

## Repo layout

```
data/      download + build Parquet, sample_sessions.json
sql/       features.sql (portable ANSI feature engineering)
src/core/  features.py, nba.py, predict.py   (shared train + serve)
src/train/ train.py   (fit, handle imbalance, eval, save artifacts + schema)
src/serve/ app.py      (FastAPI, one POST /predict calling core.predict, CORS for React)
models/    model.json, pipeline.joblib, feature_schema.json
frontend/  React app, API base URL from env
config/    .env.example
```
